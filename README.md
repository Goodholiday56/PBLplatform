## 项目背景

2026 年 4 月 19 日，北京亦庄半程马拉松暨人形机器人半程马拉松正式开跑。约 21 公里的赛道上，1.2 万名人类跑者与 100 余支机器人赛队的 300 多台人形机器人共同奔跑——这是体育赛事与前沿科技融合的历史性时刻。

人形机器人从"站稳都很费劲"到"实现自主奔跑"，折射出人工智能、高端制造、运动控制等技术的加速融合。国家层面，《人形机器人创新发展指导意见》已将人形机器人纳入未来产业和新质生产力的重要框架，"具身智能"被列为重点培育的未来产业之一。

**本项目将这一真实科技事件转化为跨学科学习情境**，引导初三升高一学生以"科技赛事研究员"身份，从地理、物理、数学、信息技术、语文、英语等多学科视角，探究赛事选址、机器人原理、成绩分析与科技传播，在"科技、城市与社会"的联系中发展核心素养。

> 📖 完整教学设计见 [`项目背景.md`](./项目背景.md)（12 课时详细教案），教师操作指南见 `操作文档.md`。

## 教学设计理念

| 理念 | 说明 |
|------|------|
| **项目式学习 (PBL)** | 以真实情境驱动，学生以角色身份（科技赛事研究员、机器人设计者、科技传播者）参与，在解决真实问题中综合运用多学科知识 |
| **跨学科主题学习** | 以一门课程为主干，整合地理、物理、数学、信息技术、语文、英语、政治、美术 8 门学科，实现知识的融会贯通 |
| **支架式教学** | 基于维果茨基"最近发展区"理论，通过资料包、问题提示、图表模板、表达框架和评价量规提供学习支架 |
| **做中学、评中改、展中学** | 学习闭环：真实任务 → 初步成果 → 接受反馈 → 修改完善 → 公开展示，在实践和反思中深化理解 |

## 技术栈

### 前端
- **纯 HTML/CSS/JS** — 无框架、无构建工具，降低教师部署门槛
- **Material Design 3 风格** — 种子色 `#6750A4`，系统字体栈
- **Leaflet + 高德瓦片** — 交互式地图（库文件本地化，无 CDN 依赖）
- **纯 CSS 图表** — 不使用 Chart.js / ECharts 等第三方图表库
- **响应式布局** — 桌面 / 平板 / 手机端适配

### 后端
- **Node.js 原生 HTTP 服务** — 无 Express 等框架依赖，仅使用 `http`、`fs`、`path`、`crypto` 标准库
- **JSON 文件持久化** — 用户、进度、作品、评论等数据存储于 `data/` 目录
- **Session 机制** — 基于随机 token 的简易登录态管理

### AI 集成
- **DeepSeek API** (`deepseek-chat`) — 通过服务端 `/api/ai` 端点代理，API Key 不暴露到前端
- **四种辅助能力**：
  - 术语通俗化 — 用生活类比和场景拆解解释专业概念
  - 文案润色 — 优化学生作品逻辑与表达，标注修改处
  - 英文翻译 — 产出适合初中生阅读的英文版本
  - 内容合规检查 — 核查科技事实准确性与表述规范性
- **AI 辅助、人工原创** — 所有 AI 输出标注"AI 生成，请人工复核"

### 核心依赖

| 依赖 | 用途 | 来源 |
|------|------|------|
| Leaflet 1.9.4 | 交互式地图 | `lib/` 本地文件 |
| 高德地图瓦片 | 地图底图 | 高德 API（免费配额） |
| DeepSeek API | AI 助手 | `api.deepseek.com` |
| Node.js ≥ 16 | 运行环境 | 原生 HTTP 模块 |

## 本地运行

### 前提条件

- Node.js ≥ 16.0.0
- （可选）DeepSeek API Key — 不配置时 AI 功能以 Demo 模式运行

### 安装与启动

```bash
# 1. 克隆仓库
git clone <repo-url>
cd 平台

# 2. （可选）配置 DeepSeek API Key
cp .env.example .env
# 编辑 .env，填入你的 DEEPSEEK_API_KEY

# 3. 启动服务
node server.js

# 4. 浏览器打开
# http://localhost:8000
```

### 默认账号

首次启动时自动创建，账号同上（教师 `teacher` / 学生 `student`，密码 `123456`）。

### 教师发布控制

教学资料随教师活动发布逐批展示。教师可在后台选择性地发布各模块课时——未发布的课时对学生隐藏。此机制通过 `data/publish_state.json` 中的 `materialGate` 映射实现，确保学生按教师节奏循序渐进。

## AI 辅助原则

| 原则 | 说明 |
|------|------|
| **AI 辅助、人工原创** | AI 定位为"辅助工具"而非"替代创作者"，学生需独立完成核心创作 |
| **透明可辨** | 所有 AI 输出强制标注"AI 生成，请人工复核"，引导学生批判性看待 AI 内容 |
| **合规优先** | AI 调用通过服务端代理，API Key 不暴露；学生提问经 Edge Function 中转 |
| **反思机制** | 学生使用 AI 后需填写反思日志，复盘"AI 帮了我什么"与"我独立完成了什么" |
| **人机对比** | 平台可同时展示 AI 生成作品与人工作品，引导学生对比分析各自优势 |

### AI 助手交互方式

- **浮动助手面板** — 学习视图右侧固定面板，学习过程中随时提问
- **快捷提问按钮** — 按模块预置常用问题，一键发送
- **自由输入** — 学生可自行输入问题
- **创作工坊内嵌** — 在作品编辑器中内嵌 AI 辅助按钮（术语通俗化、润色、翻译、合规检查）

## 技术约束与工程决策

| 约束 | 原因 |
|------|------|
| **零外部 CDN 依赖** | 确保校园网络环境下可用，不受外网波动影响 |
| **纯 CSS 图表** | 避免引入第三方 JS 图表库，保持前端零依赖 |
| **单文件原型** | V1.0 阶段以单 HTML 文件快速验证教学逻辑 |
| **JSON 文件存储** | 原型阶段避免数据库部署成本，`data/` 目录即数据库 |
| **Node.js 原生 HTTP** | 不引入 Express/Koa，降低依赖面，代码透明可读 |
| **AI 服务端代理** | API Key 安全，请求/响应可审计 |
